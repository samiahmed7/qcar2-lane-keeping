# Project Memory

- 2026-05-24: `src/qcar2_autonomous_lanes` Phase 1 perception is now the active new scaffold work. `bev_lane_detector_node` subscribes to `/qcar2/front_camera/image`, thresholds white lane lines in a lower ROI, detects left/middle/right x peaks, publishes `LaneModel` on `/qcar2/lane/model`, and publishes `/qcar2/lane/debug_image`. It only sets the right-lane target when middle dashed and right solid lines are visible; controller/memory behavior is intentionally not implemented yet.
- 2026-05-22: LiDAR obstacle stop is confirmed working in simulation. `/qcar2/safety_status` showed `scan=OK` and front obstacle ranges around `1.39m -> 1.06m`; after tuning the safety gate to slow below `1.80m` and hard-stop below `1.20m`, the car stops. Future LiDAR debugging should start from threshold/placement/arc tuning, not from assuming the LiDAR bridge is missing.
- 2026-05-22: Safety/lane-change guardrails now fail closed: `safety_filter` stops on `scan=MISSING` or `scan=STALE`, `lane_change_manager` blocks lane-change starts on stale LiDAR, and lane changes only commit when `/qcar2/lane_filter/state` has a fresh measurement age.
- 2026-05-22: Current IPM calibration reports the active lane corridor as about `0.69 m` (`width_obs≈0.690` in lane_filter logs), even though the generated default world has `LO=0.40`. Use the observed IPM metric width for lane-change blending unless the IPM calibration is redone.
- 2026-05-22: During dashed-middle gaps, two visible non-dashed lines should be treated as the two outer solid boundaries when their BEV separation is about two lane widths; lane_filter then projects the selected lane centre from the known corridor width instead of relabeling a solid line as the dashed middle.
- 2026-05-22: Manual lane change LEFT is confirmed working after increasing LiDAR stale timeout to `2.0s` and using observed lane width `0.69m`: logs show `Starting lane change LEFT width=0.690m lane 0->1`, `mode=BLEND 0->1`, `Lane change complete. lane_index=1`, then `mode=LANE 1 PAIR`.
- 2026-05-22: Avoid stack now starts an automatic LEFT lane change from lane `0` to lane `1` when front LiDAR range falls below `2.20m`; safety still slows below `1.80m` and hard-stops below `1.20m`.
- 2026-05-22: Lane-change midpoint `COAST` was caused by `lines=1 ids=[none]` near dashed-middle gaps. `lane_filter` now keeps short identity memory and allows weaker single-line updates only while a lane change is active, so watch logs for `*_weak` or `memory` identity sources instead of long `COAST` stretches.
- 2026-05-22: Safety stop was too conservative for passing because it used an angular front cone. `safety_filter` now stops/slows only for LiDAR points inside a forward collision corridor (`front_min`, `front_y`) and reports the old angular cone separately as `arc_min`.
- 2026-05-23: Lane-change manager now clusters nearest forward LiDAR returns and estimates obstacle lateral span/width (`obj_y`, `obj_w`). Auto/manual lane changes can request lane width plus `extra` clearance, and `lane_filter` honors offsets beyond one lane width as lane 1 plus a temporary lateral shift.
- 2026-05-23: Debug screenshot showed the car still stopping at `a=1.00 extra=+0.09 offset=+0.790`; clearance was active but too small. Tuned avoid launch to use `obstacle_min_extra_offset_m=0.18`, width padding, dynamic clearance-target increases, stronger lateral gain, lower heading gain, and faster steering rate.
- 2026-05-23: `safety_filter` now uses fresh `/qcar2/lane_filter/state` for a path-aware LiDAR swept-volume check. In `mode=PATH`, old-lane obstacles may appear in `arc_min`, `corridor_min`, or `obj_*`, but slow/stop is controlled by `path_min`; stale lane state falls back to the conservative car-centred corridor.
- 2026-05-23: Path-aware safety initially used an over-wide `0.30m` band (`vehicle_half_width_m=0.18`, margin `0.12`), causing a false stop with `path_err=0.29m`. The QCar2 URDF body is about `0.16m` wide, so safety now uses `vehicle_half_width_m=0.10` and `path_safety_margin_m=0.08` (`path_band=0.18m`).
- 2026-05-23: A second false stop happened beside the box because near-body safety was too wide and path checks started at the LiDAR origin. `safety_filter` now starts path overlap at `x=0.30m` and uses a narrow near-body strip (`x<=0.30m`, `|y|<=0.07m`) so side returns while passing are ignored unless they are directly in front of the car.
- 2026-05-23: Reverted the experimental LiDAR bypass/no-forced-extra lane-change changes after they made behavior worse. `lane_filter_avoid.launch.py` is back to the earlier obstacle clearance tuning and both safety stop plus manager-side LiDAR abort are active again.
